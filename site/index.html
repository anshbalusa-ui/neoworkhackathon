01 / System boundary

Proposal is not permission.

Trusted browser chrome captures the task. The observer and model handle untrusted data. Only the gateway may issue a scoped execution grant.

Trusted · 01

User intent

Immutable session, origin, operations, price ceiling, TTL and explicit prohibitions.

Untrusted · 02

Page observation

Product facts, reviews, hidden text and ARIA remain data with provenance.

Proposal only · 03

Planner

One typed action at a time; no actuator, script, network, or secret-store tools.

Enforcement · 04

Action Gateway

Deterministic intent, target, destination, data, effect and confirmation checks.

Privileged · 05

Actuator + fence

One-use grant; revalidate DOM; mediate redirects/requests; verify and audit.

Trust boundaryObservation → proposal does not cross into execution authority. A page instruction never changes the intent record.

Why this is different from prompt classification

A jailbreak detector tries to decide whether text looks malicious. Here the text can persuade the model completely and still cannot change the user's independently registered task. 06 / Risk policy

Confirm only what is authorized.

Effects, recipient and browser state decide the tier—not a button label, role-played system message, or model confidence.

07 / Threat coverage

What stops. What remains.

17 classified threats, including every required injection surface. STOPPED outcomes describe the proposed boundary with production interception; the simulator only proves local policy rules.

STOPPED BY DESIGN

Authority laundering

Fake system text, forged observations, unauthorized destinations, sensitive disclosures and reused grants have no independent execution authority.

REDUCED

Races and handlers

Revalidation, exact egress profiles and fail-closed attribution narrow DOM swaps and click-handler effects; real browser integration is a release gate.

ACCEPTED RISK

Factual manipulation

The gateway cannot prove a product review, price or inventory is true. Malicious first-party semantics and trusted-runtime compromise need separate controls.

08 / Engineering handoff

Build the boundary, then launch.

The reference gate runs without credentials or external APIs. It is deliberately not a production browser interceptor.

01 · Contracts

Isolate intent and proposals

Browser-owned signed registry, versioned schemas, provenance-bearing observations, unknown-op default deny.

02 · Enforcement

Own browser effects

Native grants and UI, current handles, event attribution, pre-request/redirect fence across frames and workers.

03 · Release gate

Verify before autonomy

Browser-level race and egress tests, privacy review, red-team assessment; observe-only if mediation is incomplete.
