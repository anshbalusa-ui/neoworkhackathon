01 / The boundary

The model proposes.
The gateway decides.

The Action Gateway is the execution authority, not the webpage or model. Unknown browser effects fail closed.

TRUSTED · 01User intent

Direct native request, scoped tab/origin/operation/expiry

UNTRUSTED · 02Page observer

DOM, content, labels and browser-issued handles

PROPOSAL · 03Read-only planner

Emits one typed action, no tool execution

GATE · 04Policy engine

Validate signed intent, DOM, effect, approval

ACTUATOR · 05Network fence

One-use grant and pre-effect traffic mediation

Hard boundary: instructions from a review, comment, hidden element or screenshot never become user permissions. Browser JS side effects require actual network interception.

03 / Confirmation logic

No silent side effects.

Approval follows verified consequences, not button text or model confidence.

AUTONOMOUS · V1

Public and bounded

Exact search value, local filter, allowlisted same-origin GET in an anonymous read-only context with fully mediated egress.

CONFIRM · FUTURE ADAPTER

Externally visible

RSVP, messages, posted content, persistent settings; must have reviewed adapter and native, exact-scope approval. Not enabled by default in v1.

DENY · V1

Unknown or high impact

Payments, credentials, account security changes, uploads, unreviewed cross-origin changes, any unmediated network effect.

04 / Engineering handoff

A proposal with an enforceable boundary.

If browser-level request interception is unavailable, agent action mode must remain read-only.

Documents, not security theater

Use the architecture decision record, threat model and confirmation policy as implementation contracts. The reference tests prove only a local deterministic policy simulator, not deployed Norton Neo browser defenses.
